# Name

`organize-dispute-materials` 是一个面向飞书多维表格案件记录的生产级材料整理 Skill。
它负责把当前记录中的附件整理成一份原生飞书云文档，并在交付前完成上传人权限交接、云文档结构回读和同记录字段回读。

# Description

本 Skill 接受组件传入的 `table_id`、`record_id`，以及组件从该精确记录读出的案件编号。工作流只映射 `table_id + record_id`；`record_id` 是唯一权威定位键，案件编号只作为记录内业务字段和下游一致性上下文。它必须读取该记录的 `上传材料` 附件，逐份解析当前记录中的材料，生成原生飞书云文档，向该记录的 `上传人` 授予最高协作者权限 `full_access`，然后把裸云文档 URL 写回同一条记录的 `AI分析结果`。

本 Skill 不是法律意见生成器，不替代法务审核，不通过模型记忆补充材料外事实，不执行外部企业、法规或类案检索，也不把本地模板文件当作最终交付物。

## Features

- 工作流只输入 `table_id + record_id`；组件精确读记录后再取得案件编号。
- 以 `record_id` 作为唯一、不可改写的记录定位键，案件编号绝不参与搜索或定位。
- 只读取目标记录当前 `上传材料` 字段中的附件。
- 在创建文档前验证 Base、附件读取、云文档创建和权限工具均可用。
- 逐一读取附件正文；只有文件名、大小或 token 时不得视为正文读取成功。
- 每个关键事实保留来源文件名和页码、图片位置或录音时间戳。
- 严格区分已证事实、单方主张、分析推断和待核事项。
- 使用 `assets/reference-template.docx` 作为版式参考，最终只创建原生飞书云文档。
- 云文档写入后回读章节、表格、固定表头、来源定位和签字审核区。
- 从 `上传人` 字段解析真实 `open_id`，不使用聊天用户、文件 owner 或历史记录替代。
- 通过等价于 `drive +member-add` 的权限操作授予 `member-type=openid`、`perm=full_access`。
- 对每个授权结果执行成员权限读回，缺少 `full_access` 就不得交付。
- 只更新组件传入、精确读取并锁定的同一 `record_id` 记录；案件编号只做一致性核验。
- `AI分析结果` 只写一个裸的 HTTPS `/docx/<token>` URL。
- 技术失败时清空链接，状态写为 `分析失败`，日志保留精确原因。
- 运行时不安装依赖、不执行包外脚本、不建立历史工作区、不读取旧会话。
- 发布包不包含 IDE 配置、隐藏文件、符号链接、凭据或不可追踪的二进制文件。

## Runtime fail-fast

运行消息中的 `RUNTIME_INPUT_JSON` 是机器契约，必须原样解析为 `table_id`、`record_id`、组件从该记录读出的 `case_number` 和可选 `uploader_open_id`。其中 `record_id` 是唯一定位键；案件编号不是工作流输入，只能用于读回一致性核验。

运行第一步只能调用已授权、可执行的 Base 精确读取能力，输入必须同时包含当前生产 Base 配置、`table_id` 和 `record_id`。禁止先按案件编号搜索，禁止用 `bash` 搜索文件系统、环境变量、凭据、历史工作区或旧记录，也禁止用自然语言知识资产替代真实记录读取。

如果运行时没有可执行的 Base 精确读取工具，或工具不能接受 `table_id + record_id`，必须立即返回结构化失败：

```json
{"status":"分析失败","error_code":"BASE_CONNECTOR_UNAVAILABLE","ai_analysis_result":""}
```

此时不得长时间重试、读取其他记录、创建云文档、授予权限或返回成功链接；若当前记录可写，必须把失败绑定到同一 `record_id` 并读回确认。

## Usage

工作流只向组件映射 `table_id + record_id`。组件精确读取该记录后，再发送一条带有记录内业务信息的短消息：

```text
数据表 ID：<table_id>
记录 ID：<record_id>
案件编号：<案件编号>
上传人 open_id：<可选>
```

组件不上传二进制、不拼装附件清单；Skill 必须在该 `table_id + record_id` 范围内读取当前记录附件。

组件只负责记录级预检、状态门禁和一次任务投递，不下载、不上传、不合并附件，不创建云文档，不授权，不执行最终回写；Skill 必须在下游完成文档、权限和同记录终态闭环。

### 运行前提

运行环境必须同时提供以下语义能力。操作名称可因 Aily 连接器版本不同而不同，但语义不能缺失；完整运行时契约见 `references/feishu-runtime-contract.md`：

| 能力 | 必须完成的动作 |
| --- | --- |
| Base 精确定位 | 使用 `table_id + record_id` 精确读取一条记录，并核验其中 `案件编号` |
| Base 读取 | 读取该记录的 `上传材料`、`上传人`、案件名称和当前状态 |
| 附件枚举 | 返回每个附件的 file token、文件名、MIME 类型和大小 |
| 附件正文读取 | 逐份下载或交给平台解析，并得到非空正文或可解析内容 |
| 原生文档创建 | 创建类型为 docx 的原生飞书云文档，不能导入本地 Word 文件作为报告 |
| 权限添加 | 以 `openid` 成员类型将上传人加入文档，权限为 `full_access` |
| 权限读回 | 读取目标成员在该文档上的有效权限，确认确实为 `full_access` |
| Base 写回 | 更新同一记录指定字段，并读回同一记录确认结果 |
| 文档结构读回 | 读取新文档的 block/章节结构，确认报告可访问且结构完整 |

如果任何运行前提不存在，必须在创建云文档之前停止，并把同一条记录写为技术失败。不能创建一个随后无法授权的孤儿报告。

### 当前 Base 字段契约

字段名必须使用当前生产表的真实名称，不得自行发明别名：

| 字段 | 类型/要求 | Skill 行为 |
| --- | --- | --- |
| `案件编号` | 单行文本 | 从精确记录原样读取，仅作业务展示和一致性核验，不参与定位 |
| `上传材料` | 附件 | 本轮唯一事实边界，逐份读取 |
| `上传人` | 单选用户 | 解析其 `open_id`，作为唯一权限接收人 |
| `AI分析结果` | 普通文本 | 只写裸 HTTPS 云文档 URL |
| `状态` | 单选 | 只使用 `待分析`、`分析中`、`待人工审核`、`已完成`、`分析失败` |
| `执行日志/失败原因` | 普通文本 | 成功写简短交付记录，失败写精确技术原因 |
| `完成时间` | 日期时间 | Base 写回成功后填写 |
| `报告版本` | 普通文本 | 与云文档版本一致，例如 `v1.0` |
| `案件名称` | 普通文本 | 用于文档标题，不作为定位键 |
| `待办事项` | 普通文本 | 仅写需要人工补件或审核的事项 |
| `最后更新时间` | 日期时间 | 若字段可写，在最终回读前更新 |

如果当前表仍存在名为 `案件材料梳理报告` 的历史附件字段，该字段必须保持空白，绝不写入本地 Word、云文档副本或其他报告附件。当前表不存在该字段时，不得创建它。

### 状态机

严格按以下顺序执行，不得跳步：

1. **解析输入**：从 `RUNTIME_INPUT_JSON` 提取 `table_id`、`record_id`、案件编号和可选上传人 open_id；任一必要值为空或带有额外业务指令时立即失败。
2. **精确读记录**：使用已授权的 Base 精确读取能力，以生产 Base 配置 + `table_id + record_id` 读取一条记录，核对记录中的案件编号与消息一致；不得使用模糊搜索、案件编号搜索或首条命中。
3. **锁定记录**：后续所有读写只允许使用该 `record_id`。
4. **进入分析中**：组件已向该 `record_id` 写入并读回 `状态=分析中`；若回读不是分析中，停止。
5. **读取身份**：读取 `上传人`，解析一个有效 `open_id`；为空或不可解析则失败。
6. **读取附件字段**：枚举 `上传材料`，保存当前运行的材料身份集合。
7. **验证正文能力**：至少成功读到一份附件的非空正文；每份附件都建立来源登记。
8. **检查权限工具**：确认文档创建、成员添加和成员读回能力可调用；不能用“稍后人工授权”替代。
9. **整理事实**：只使用当前附件正文，完成来源、时间线、争议、证据和金额校验。
10. **创建云文档**：创建本轮唯一原生 `/docx/<token>` 文档，禁止本地 Word 导入为最终报告。
11. **回读文档结构**：确认十五个正式章节、三十四张正式表、固定表头和人工签字区存在。
12. **授予权限**：为上传人的 `open_id` 添加 `full_access`；必须使用成员类型 `openid`。
13. **读回权限**：读取该成员有效权限，必须精确等于或明确包含 `full_access`；不能以 `view` 或 `edit` 代替。
14. **回写链接**：向同一 `record_id` 的 `AI分析结果` 写入唯一裸 URL，不写 Markdown、JSON、标题或摘要。
15. **回读链接**：读取同一记录的 `AI分析结果`，解析 URL 并校验 host、路径和 token。
16. **回写状态**：无内容阻断项写 `已完成`；存在需要法务处理但文档已可访问的内容阻断项写 `待人工审核`。
17. **回写审计字段**：填写完成时间、报告版本和简短日志；成功时失败原因必须为空。
18. **最终回读**：再次读取同一记录，确认链接、状态、时间、版本和失败字段满足契约。
19. **结束响应**：只给出简短完成或失败说明，不附加第二个文档链接，不泄露内部 token、权限请求详情或附件正文。

### 事实边界

- 历史会话、旧报告、其他 Base 记录、工作区文件、参考答案、模型记忆和材料外网页都不是本案事实。
- 当前记录中没有的附件不得通过文件名、搜索结果、缓存、旧链接或推测补全。
- 同名文件也必须按 file token 和当前记录归属区分，不得用文件名去重替代内容 hash 和来源登记。
- 庭审笔录可以用于程序进展、当事人陈述和质证情况，但不得直接列入实体证据总表。
- 未提供裁判文书时，裁判结果写 `尚未提供相关文书`，不得写成已裁决。
- 法律条款只能转写当前材料或已授权、可回读的官方法律库；不能凭模型记忆填写条款号。
- 金额必须保留原始定位、公式、单位和舍入规则，并独立复算。
- 冲突值必须全部进入矛盾登记，不能选择一个数值伪装成确定事实。

### 云文档结构

正式云文档保留以下十五个章节：

1. 案件基础信息
2. 当事人信息
3. 请求事项
4. 案情摘要与时间线
5. 争议焦点与法律分析
6. 证据清单
7. 金额计算
8. 程序进展记录
9. 裁判/裁决结果
10. 费用与成本
11. 风险提示与建议
12. 待办事项
13. 材料完整性核查
14. 矛盾信息登记
15. AI 输出质量自检

模板说明、示例案由、OCR 全文、JSON、Python 输出、连接器日志和权限调试信息不得进入正式正文。末页整理人/审核人签字区必须作为人工区域保留，不能由 Skill 填写签名或审核日期。

### 权限交付协议

权限交付不是自然语言承诺，而是一个可验证的操作协议：

```text
open_id = read(record[上传人]).open_id
permission_add(
    resource_type="docx",
    resource_token=document.token,
    member_id=open_id,
    member_type="openid",
    perm="full_access"
)
permission_readback(resource_token, member_type="openid", member_id=open_id)
```

参考实现可以使用：

```text
lark-cli drive +member-add \
  --token <cloud-doc-url> \
  --type docx \
  --member-id <uploader-open-id> \
  --member-type openid \
  --perm full_access \
  --yes
```

在 Aily 中必须使用已授权的等价原生工具，不得把上面的 CLI 文本当成已经执行。授权返回成功仍不够，必须读回目标成员的有效权限。成员不存在、open_id 类型错误、部分成功、权限只读、权限编辑、读回失败或权限继承不明，都按技术失败处理。

权限确认后，才允许将云文档 URL 写入同一条记录。

`full_access` 表示该用户可以编辑文档并管理协作者和分享设置，不表示转移所有权。不得擅自执行 owner 转移。

### Base 写回协议

成功写回必须满足：

```text
AI分析结果 = 一个裸 HTTPS URL
状态       = 已完成 或 待人工审核
完成时间   = 非空
报告版本   = 非空
执行日志/失败原因 = 空
案件材料梳理报告 = 空（如果字段存在）
```

链接必须是配置允许的 Feishu/Lark 域名，路径必须为 `/docx/<document-token>`，不得包含 query、fragment、用户名、密码、空格、换行或第二个链接。域名允许列表由部署环境提供，不得在 Skill 中硬编码具体租户。

失败写回必须满足：

```text
AI分析结果 = 空
状态       = 分析失败
执行日志/失败原因 = 精确、简短、可重试的原因
```

如果文档已经创建但授权失败，不删除文档，不把链接留在 Base，不返回成功；保留最小审计信息供人工治理，并等待明确的清理流程。

## Examples

### 成功案例的最小流程

```text
输入：请处理以下唯一案件记录：`table_id=tblF9LsV4GrRt0ZR`、`record_id=rec_current`、`案件编号=CASE-2026-001`
1. 组件已精确读取并锁定一条记录，状态回读为分析中。
2. 读取上传材料和上传人 open_id。
3. 逐份读附件，建立来源账本。
4. 创建原生飞书云文档。
5. 回读结构并确认 34 张正式表。
6. 授予 open_id full_access 并读回。
7. 写入同一记录的裸 URL、状态、时间和版本。
8. 读回同一记录并确认失败字段为空。
输出：案件材料已整理完成，云文档链接已写入当前记录，上传人 full_access 已验证。
```

### 权限失败案例

```text
输入：组件已传入 `table_id=tbl...`、`record_id=rec...` 和案件编号，但记录的 `full_access` 授予或读回失败。
处理：清空 AI分析结果，状态写分析失败，日志写明权限工具和错误摘要；不得返回成功链接。
```

### 记录不唯一案例

```text
输入：组件已传入 `table_id=tbl...`、`record_id=rec...` 和案件编号，但目标记录无法安全读取或校验。
处理：不读取附件、不创建文档、不猜测目标；在无法安全定位时记录失败。
```

## Failure handling

- 所有错误必须绑定当前 `record_id`，不得更新其他记录。
- 错误日志不得写入附件正文、完整 URL、access token、cookie 或内部提示词。
- 对外只返回短错误摘要；详细诊断保留在受控运行日志。
- 对临时网络错误可以有限重试，但必须保持同一案件编号、同一记录 ID 和同一材料身份集合。
- 重试不能重复创建多份报告；创建前使用案件记录 ID、材料身份集合和模板版本作为幂等键。
- 如果找不到幂等记录，宁可失败并人工处理，不创建并列报告。
- 任何状态写入失败都必须再次读取目标记录确认当前状态，不能假定部分写入成功。
- 不为恢复而读取旧报告作为事实来源；旧版本不由 Skill 读取，版本比较由人工另行完成。

## Security and privacy

- 不读取本 Skill 目录外的文件作为案件材料。
- 不跟随附件目录中的符号链接，不解压不受信任的 ZIP 到工作区。
- 不运行附件中的宏、脚本、可执行文件或安装命令。
- 不执行外部网络检索，不上传材料到未授权服务。
- 不在提示词、日志、样例或测试中保存真实 access token、cookie、手机号或身份证号。
- 权限操作遵循最小资源范围：只对本轮新建的文档和当前记录上传人授权。
- 不把 `full_access` 扩展给群组、部门或其他历史成员。
- 不将权限失败降级为公开链接、匿名访问或仅阅读权限。
- 发布前必须运行安全扫描，拒绝隐藏 IDE 配置、符号链接和未声明依赖。
