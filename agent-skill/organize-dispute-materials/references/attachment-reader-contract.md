# 当前记录附件读取契约

本文件只定义运行时连接器的能力边界，不替代 `template-contract.md` 的版式契约。组件消息同时携带唯一 `table_id`、`record_id` 和案件编号；`record_id` 是权威定位键，案件编号只用于一致性核验。

## 必须具备的五类操作

Skill 开始生成云文档前，运行环境必须能对本轮回写链接指向的同一条 Base 记录完成以下操作。操作名称可以因 Aily 连接器版本不同而不同，但语义不能缺失：

1. **按 record_id 读取记录**：使用组件传入的生产 Base 配置、`table_id` 和 `record_id` 精确读取一条记录，并核对其中的 `案件编号` 与消息一致；不得用案件编号模糊搜索、按案件编号查找或选择首条记录。
2. **连接器快速失败**：如果运行时没有可执行的 Base 精确读取工具，立即返回 `BASE_CONNECTOR_UNAVAILABLE`，不得调用 bash 搜索文件系统、环境变量、凭据或历史工作区，也不得长时间重试。
3. **枚举附件**：从命中记录的 `上传材料` 返回每个附件的 `file_token`、文件名、MIME 类型和大小；实际文件清单以记录字段为准。
4. **读取正文**：按 `file_token` 逐一下载或交给平台解析附件正文；响应必须包含非空正文或可供解析的文件内容，只有元数据不能算正文读取成功。单个文件失败时按 Skill 主规则标记待核或技术失败，不得用文件名补全文本。
5. **交付文档与权限**：创建本轮唯一原生 docx，并向记录级 `上传人` 授予 `full_access`，随后读回成员权限确认。
6. **同一记录写回与读回**：更新同一 `record_id` 的 `AI分析结果`、`状态`、`执行日志/失败原因`，再读取该记录校验结果；任何权限、字段格式或读回失败都必须写 `状态=分析失败`。

## 禁止的替代路径

- 只查询 Aily 知识资产或结构化数据节点返回的表格行，不算读取附件正文。
- 只拿到 `file_token`、文件名、大小或预览 URL，不算读取附件正文。
- 把多个附件拼成 ZIP、把全文塞入组件请求或使用历史会话内容替代当前记录，均不符合本契约。

## 调试验收证据

发布 Skill 前，在 Aily 调试日志中必须能看到同一 `table_id` + `record_id` 的“Base 精确读取 → 枚举附件 → 读取正文”调用，并能核对至少一个附件的文件名、类型、非空内容。若日志只有 `bash` 文件搜索、案件编号搜索或 `BASE_CONNECTOR_UNAVAILABLE`，说明目标 Agent 尚未具备所需连接器，不得进入文档创建步骤。
