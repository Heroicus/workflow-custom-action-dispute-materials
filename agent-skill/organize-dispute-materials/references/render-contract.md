# 固定 XML 渲染契约

`report-template.xml` 是唯一格式源。运行时先形成来源明确的案件数据，再把数据代入模板，最后一次性创建或全文重写云文档。不得复制远程模板，不得逐块修改表格。

## 渲染步骤

1. 读取 `report-template.xml` 原文；
2. 将每个 `{{name}}` 替换为 XML 转义后的材料事实；空值替换为空字符串；
3. 将每个 `<!--name_rows-->` 替换为零行或多行 `<tr>...</tr>`；
4. 确认最终 XML 中不存在 `{{`、`}}`、行标记或占位词；
5. 初次处理用完整 XML 创建文档，补充处理用完整 XML 全文重写原 document token。

文本转义：`&` → `&amp;`，`<` → `&lt;`，`>` → `&gt;`，正文换行 → `<br/>`。不得转义 XML 标签。

## 标量字段

普通 `{{name}}` 的业务含义由它所在单元格左侧标签决定。金额汇总字段使用：

```text
principal_*        本金/应退款项
penalty_*          违约金
interest_*         资金占用利息
lawyer_fee_*       律师费
preservation_fee_* 保全/公证费
case_fee_*         诉讼费/仲裁费
total_*            合计
```

其中 `*` 为 `formula / start / end / rate / amount`。费用与成本使用 `<费用英文名>_budget / actual / note`。没有材料事实时全部为空。

## 动态行

每行必须按下列列顺序输出 `<td><p>值</p></td>`。数组为空时删除行标记，不生成空白数据行。

| 行标记 | 列顺序 |
|---|---|
| `request_rows` | 序号；请求事项；类别；金额；依据；证据 |
| `counterclaim_rows` | 序号；反诉/反请求；金额；依据；证据 |
| `timeline_rows` | 序号；日期；事实；来源材料；备注 |
| `fact_dispute_rows` | 序号；争议事实；我方记载；对方记载；证据对比；待核事实 |
| `focus_rows` | 序号；争议焦点；类型；重要程度 |
| `our_argument_rows` | 序号；焦点；我方材料记载；事实/法律依据；证据 |
| `opposition_rows` | 序号；对方材料记载；类型；材料已有反驳；材料已有补强要求 |
| `legal_basis_rows` | 序号；法律/合同名称；条款；原文摘要；适用要件；证据 |
| `evidence_rows` | 编号；名称；类型；证明目的；原件情况；页数；日期；材料已有备注 |
| `evidence_group_rows` | 组别；组名；证据编号；证明目的 |
| `opponent_evidence_rows` | 编号；名称；对方证明目的；材料已有质证意见；材料已有鉴定要求 |
| `evidence_defect_rows` | 序号；问题证据；材料明确瑕疵；风险原文；补强原文；负责人/期限 |
| `calculation_detail_rows` | 序号；期间；基数；日利率；天数；金额 |
| `procedure_rows` | 日期；事项类型；内容；承办人；附件编号 |
| `preservation_rows` | 类型；日期；事项/标的；担保/费用；结果/意见 |
| `risk_rows` | 序号；材料明确风险；类型；可能性；等级；材料明确措施 |
| `precedent_rows` | 序号；案号；法院/仲裁机构；裁判要旨；可援引性 |
| `todo_rows` | 序号；材料明确待办；关联部分；负责人；期限；状态 |
| `completeness_rows` | 序号；材料原文核查项；是否具备；材料原文说明 |
| `conflict_rows` | 序号；事项；材料A原文；材料B原文；材料已有处理意见 |

## 事实规则

- 当前记录和附件正文是唯一事实来源；
- Base 案件编号可以写入报告，其他业务字段仍须有材料依据；
- `风险、建议、缺失材料、补强、质证、重要程度、胜诉概率` 只有材料明确记载时才填；
- 原件、复印件、盖章件只有材料明确说明时才填；
- 法律条款只转写材料实际出现的名称、条号和摘要；
- 金额和公式只转写材料明确值，不自行生成另一套计算结果；
- 同一材料内部或不同材料之间数值冲突时，保留原文并写入 `conflict_rows`；
- 不使用 `未载明、未提供、暂无、不适用、待确认、需补充、人工复核、人工填写` 填充空值；
- 不把内部推理、工具日志、结构检查和 JSON 写进报告。

## 结构验收

最终 XML 和云文档读回必须保持：

```text
15 个一级章节
22 个二级章节
34 张表格
末尾整理人/审核人签字区
```

章节与表格顺序必须与 `report-template.xml` 一致。数量正确但表格移动到其他章节或签字区之后仍然失败。结构失败时只允许用同一完整 XML 重新创建或全文重写一次，不进行增量修补。
