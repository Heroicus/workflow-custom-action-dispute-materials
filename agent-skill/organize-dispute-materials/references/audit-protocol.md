# 律师工作底稿：事实、法律与质量审校协议

本协议将正式报告定义为**可追溯、可审计的律师工作底稿**，不是最终法律意见、裁判预测或替代人工法务结论。所有生成、渲染、回写均受本协议约束。

## 1. 输出前的四类结构化账本

在写入正式报告前，先在本轮工作记忆中完成下列账本；不得把 JSON、内部 ID 或原始 OCR 全文写入正式报告。

### 1.1 材料/证据账本

每份当前附件和每项已编号证据必须有：`材料名/证据编号`、材料角色、页码/图片页/录音时间戳、可读取状态、可支持的事实。

- 附件无法读取、缺页、文字不清、无原件：登记为 `待核`，注明具体文件与位置。
- 不得把庭审笔录列入实体证据总表；可用于程序进展、当事人陈述与质证情况。
- 不得把材料目录、律师意见、模板示例或旧报告当作原始事实证据。

### 1.2 事实账本

每个拟写入报告的关键事实必须先归入且仅归入一种状态：

| 状态 | 含义 | 正式报告写法 |
|---|---|---|
| 已证事实 | 原始材料直接记载，且有定位 | 直接陈述 + 来源定位 |
| 单方主张 | 仅一方当事人陈述（写明主张方称谓：原告/被告、申请人/被申请人、上诉人/被上诉人等） | `X方主张：…` |
| 分析推断 | 由材料推导，不能替代事实 | `初步分析：…；待人工审核` |
| 待核 | 缺材料、材料冲突或无法定位 | `【待核：文件名/位置/原因】` |

禁止将单方主张、推断或待核事项写成确定事实。每个“已证事实”必须至少有一个附件定位；没有定位就降级为 `待核`。

### 1.3 请求—要件—证据矩阵

每项请求/反请求必须逐项完成：请求原文、金额、主张方、前置门槛、支持事实、反向事实/对方抗辩、支持证据、材料缺口、当前风险等级。

以下任一未完成时，报告不得出现“应当支持”“构成违法”“胜诉概率”“推荐和解金额”之类确定性表达：

- 请求金额或计算口径不明；
- 请求的协议效力、时效/除斥期间、管辖、主体资格或程序状态未核；
- 对方证据或答辩材料尚缺；
- 关键事实没有来源定位。

### 1.4 法律依据账本

法律依据分两种：

1. **材料内依据**：合同条款、规章制度、仲裁申请/答辩引用的规范。必须写明材料和页码。
2. **已核验规范**：只有在本轮材料附有权威原文，或调用环境提供了已授权、可回读的官方/内部审核法律库时，才可写具体法律名称、条款号和条文摘要。

不得凭模型记忆填写法律条文、司法解释条款号、地方口径、类案案号或判决结论。不能完成原文与来源核验时，法律依据栏写：`【法律依据待法务核验；不得填写具体条款号】`。

## 2. 强制计算与一致性校验

所有金额、日期、期限、利息、违约金、比例及案件所属领域的特有计算（如劳动争议的工龄与经济补偿年限、买卖合同的逾期付款利息、借贷的本息结算），写入前必须完成：

1. 抽取原始数值及来源定位；
2. 明示计算公式、单位和舍入规则；
3. 独立复算；
4. 与请求事项、金额计算、风险、结论、时间线等全报告字段交叉比对。

发现差异时：

- 将全部冲突值记录到第十四章；
- 第七章写 `【金额/口径待核】`，不得选择任一数值冒充确定值；
- 第十五章质量状态必须为 `不通过`；
- 交付状态不得为“已完成”。

## 3. 分阶段质量门禁

写入前门禁只核验附件、来源、计算、法律依据和模板可写性。云文档结构、34 张表和签字区只能在写入后回读核验；不得把写入后检查作为写入前完成条件。

## 4. 阻断级（Blocker）质量门禁

下列任一情况为 Blocker，正式报告可生成供审阅，但必须在标题后标识 `底稿状态：待人工审核（存在阻断项）`；不得标记“质量通过”、不得回写 Base `状态=已完成`：

- 无来源定位的已证事实；
- 同一金额、日期、主体、案号或案件状态存在未解释冲突；
- 具体法条/司法解释/类案引用没有可回读的来源；
- 未填时效、除斥期间、管辖、主体资格或程序状态，而报告又给出实体结论；
- 证据目录有未映射证据、孤儿引用或编号重复；
- 报告中存在材料外的确定性事实、金额或法律结论；
- 原生文档结构回读失败。

非阻断警告：材料缺页、录音未转写、图片不清、缺少答辩/裁决/制度等。必须进入第十二至十四章，不得被“未载明”吞没。

## 5. 第十五章：独立审校表

不得由生成过程自我宣布“全部通过”。第十五章逐项填写 `通过 / 不通过 / 无法核验`，每个“不通过/无法核验”必须有原因和对应章节或材料定位。至少包含：

1. 当前附件是否全部入账，证据编号是否双向映射；
2. 每个已证事实是否有文件与页码/时间戳；
3. 是否严格区分已证事实、双方主张、推断和待核；
4. 金额、日期、期限和公式是否交叉复算一致；
5. 是否存在无来源的法条、司法解释、类案或法律结论；
6. 协议效力、时效/除斥期间、管辖、主体、程序状态是否检查；
7. 是否有证据不足却被写成确定结论；
8. 是否保留模板结构、表头、签字区且无模板示例残留；
9. 是否已完成云文档结构回读；
10. 当前结论：`可供法务审阅` / `待补材料` / `存在阻断项，不得作为意见书`。

## 6. Base 回写状态

- `已完成`：Blocker 为 0；所有强制校验通过；报告状态为“可供法务审阅”。
- `待人工审核`：报告已创建且可访问，但存在 Blocker 或关键待核事项；执行日志必须列出 blocker 编号、影响与需补材料。
- `分析失败`：创建、授权、回读或回写失败；记录精确错误。

无论何种状态，只能更新调用消息指定的同一条记录。

内部审校如需保留结构化记录，只能作为智能体内部校验数据，不得作为对外输出，也不得写入 Base 的 `AI分析结果` 字段。对 Base 回写时，`AI分析结果` 只能是配置允许域名下唯一裸的 HTTPS `/docx/<token>` URL；状态和阻断说明分别写入 `状态` 与 `执行日志/失败原因`，并对 URL 进行同字段读回校验。
