# 视觉证据契约

## 固定角色

```text
名称：纠纷材料视觉核验员
传输：平台原生智能体调用
权限：只读指定记录、指定附件和指定视觉单元，只返回证据 JSON
```

纠纷材料视觉核验员不得填写 `case-facts.json`，不得生成或修改报告，不得写入 Base、文档、云盘或权限。纠纷材料整理专员是唯一事实合并者和业务写入者。

## 输入

`vision_tool.py prepare` 读取 `runtime.json`、附件下载封印和 `vision-task/v3` 清单。每项任务必须完成以下单一链路：

1. 验证本地视觉单元的文件名、字节数、像素尺寸、转换记录和 SHA-256。
2. 将任务绑定到下载封印中的唯一 Base 附件 token、文件名、字节数和 SHA-256。
3. 由纠纷材料整理专员使用平台原生智能体调用能力调用纠纷材料视觉核验员，传入唯一 Base、表、记录、附件和视觉单元范围。
4. 视觉智能体以用户身份只读指定记录，只下载指定附件，核对真实文件字节并打开指定页面、图片或嵌入对象。
5. 将原生调用返回的唯一 JSON 原样保存，校验提示词、响应、结果和 Base 来源绑定的 SHA-256。

每项任务只能调用一次指定智能体，失败后最多重试两次。不得使用 Bash、lark-cli 或 Aily OpenAPI 创建嵌套会话。不得合并多项任务。不得传递主智能体本地路径。不得调用 Aily 附件上传接口。不得用主智能体 OCR 文字代替视觉智能体对真实附件的读取。

图片包括独立图片附件、每一页 PDF 和 Office 文件中的嵌入图片。PDF 页面固定按 300 DPI 形成本地不可变视觉单元。任务内 `ocr_text` 只用于定位，不是事实来源。视觉智能体必须重新下载 Base 中的指定原始附件；本地视觉单元仅用于任务定位和结果绑定。

## 输出

每次必须只返回符合 `vision-result-schema.json` 的一个 `vision-evidence/v3` JSON 对象。

- `verbatim_text` 只逐字转录可见内容。
- 不总结，不推断，不补全，不规范化。
- 看不清的区域写入 `uncertain_regions`。
- 姓名、机构、案号、日期、金额、利率、账号或裁判结果不确定时，`critical` 必须为 `true`。
- `status=complete` 表示没有关键内容无法辨认。
- 存在关键不确定区域时使用 `partial`。
- 整个视觉单元不可读时使用 `failed`。
- `source_sha256`、`image_sha256` 和 `task_id` 必须原样返回。
- `producer.agent_name` 固定为 `纠纷材料视觉核验员`。
- `producer` 只包含固定的 `agent_name`。
- 不得返回 Markdown、解释或契约外文字。

## 成功门

`accept` 严格解析单一 JSON 对象，不修改子智能体输出。响应文件必须逐项覆盖调用清单，不得缺失或混入未知结果。返回格式错误、非完整状态或关键内容不清时，不得把失败结果接收为完成。

`reconcile` 重新校验本地视觉单元、Base 来源绑定、原生调用回执、提示词与结果哈希、回执集合哈希、任务哈希和结果契约。缺少任务结果、Base 来源不一致、回执不完整、来源哈希不一致、返回契约外字段或仍有关键内容不清楚时，整个案件不得返回完成。
