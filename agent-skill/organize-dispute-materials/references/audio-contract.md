# 音频转写证据契约

## 固定链路

```text
原始音频附件
→ 原子复制为不可变内容快照
→ 私有上传快照校验
→ 用户身份上传到飞书云空间
→ Feishu Minutes 生成妙记
→ 轮询并远端读回逐字稿
→ audio_tool.py 校验文件、响应和逐字稿 SHA-256
→ 纠纷材料整理专员从最终语料提取事实
```

不得把原始音频交给视觉子智能体，也不得用妙记的 AI 总结代替逐字稿。音频支持 `wav`、`mp3`、`m4a`、`aac`、`ogg`、`wma`、`amr`；单文件不得超过飞书妙记的 6GB、6 小时限制。

## 职责边界

- `Feishu Minutes` 只负责远端转写；
- `audio_tool.py` 只负责上传、轮询、逐字稿读回和证据绑定；
- 纠纷材料整理专员是唯一事实合并者、报告生成者和业务写入者；
- 妙记 Summary、Todo、Chapter 和 Keyword 不得作为案件事实来源；
- 逐字稿中的姓名、日期、金额等仍须逐字出现在最终语料中，主智能体不得擅自纠正或补全。

## 幂等和补充处理

证据包把任务媒体哈希和实际上传快照哈希绑定到 `file_token`、`minute_token`、`minute_url` 和逐字稿哈希，并写入 `材料处理基线.audio_minutes` 供审计。当前没有音频转码，`source_sha256`、`media_sha256` 和上传快照哈希必须相同。同一次运行中相同媒体哈希只上传一次，复用回执必须用 `reuse_task_id` 指向原始任务。重新执行命令时即使已有本地回执，也必须再次调用 `minutes +detail --transcript` 并重建回执。Base 文本基线不是受信任凭据，跨运行不得直接复用其中的 token，补充处理重新上传当前音频。

## 成功门

每个 `audio-task/v2` 必须有一个 `audio-evidence/v2` 回执，并同时满足：

1. 音频快照位于指定任务目录，文件名、后缀、大小和 SHA-256 与任务一致；
2. 上传命令只读取从已验证文件描述符复制出的私有快照，实际上传哈希和字节数必须与任务一致；
3. 提供者固定为用户身份的 `Feishu Minutes`；
4. `minute_token` 合法，非空 `minute_url` 必须是 HTTPS 链接并且与该 token 一致；
5. 云盘上传、妙记生成和 `minutes +detail --transcript` 三段原始响应均已落盘；每段都重新解析并确认 `ok=true`、`identity=user`，token 与回执一致；
6. 非空逐字稿文件存在且哈希一致；
7. 远端返回的 `transcript_file` 必须位于本次逐字稿目录，并与回执中的相对路径指向同一文件；
8. 逐字稿已进入最终材料语料；
9. 音频任务、输入语料和最终语料的 SHA-256 与证据包一致。
