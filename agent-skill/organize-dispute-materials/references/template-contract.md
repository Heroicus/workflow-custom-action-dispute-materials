# 正式报告模板契约

正式输出唯一使用飞书新版云文档。该云文档的结构契约来自本文件；不得把本地 DOCX 导入或
转换成最终报告。创建前必须完整读取本文件的正式章节、全部表格、固定表头、签字/审核区和空值规则；
不得仅按少数字段名重建一个“相似”文档。

## 输出范围

- 保留模板正式报告的十五部分及其二、三级标题：案件基础信息、当事人、请求事项、时间线、
  争议焦点与法律分析、证据、金额、程序、裁判结果、费用、风险、待办、完整性、矛盾登记、质量自检。
- 保留固定表头，尤其是请求事项、事实时间线、证据总表、金额计算、程序节点日志、待办、
  材料完整性、矛盾信息和 AI 输出质量自检。
- 第一标题槽改为案件名称，并显示报告版本与更新时间；其余模板使用说明、案由速查、示例文本、
  填写提示、示例案号和空白预留行均不得出现在正式报告。
- 每个无来源字段填 `【未载明】`，不适用字段填 `【不适用】`；签字栏的手写横线可保留。
- 原生云文档应使用正式文档的标题、章节、表格和签字/审核区层级；不得加入模板说明、示例、
  额外封面或与案件无关的装饰内容。云文档样式以飞书原生标题、表格和段落为准。
- 模板原有 35 张表中，第一张“常见案由速查”为说明表，正式报告删除后必须恰有 34 张正式表；
  每张正式表的文档顺序、行列数、固定表头、合并关系、宽度、边框、对齐和单元格格式均不得改变。
- 末页的“整理人（法务）/审核人（法务总监）”3×2 签字表是人工签署区，必须原样保留，不得由
  AI 或脚本重写文字、横线、日期占位符、段落或单元格格式。

## 完整结构清单

1. 一、案件基础信息（2 张基础信息表）
2. 二、当事人信息（我方、对方、第三人 3 张表）
3. 三、请求事项（请求事项表、反诉/反请求表）
4. 四、案情摘要与时间线（事实时间线、事实争议点表）
5. 五、争议焦点与法律分析（焦点、我方主张、对方抗辩、法律依据 4 张表）
6. 六、证据清单（证据总表、分组、对方证据、瑕疵补强 4 张表）
7. 七、金额计算（请求金额、利息/违约金明细 2 张表）
8. 八、程序进展记录（程序节点、管辖受理、保全/鉴定 3 张表）
9. 九、裁判 / 裁决结果（裁判基础、裁判要旨、二审结果 3 张表）
10. 十、费用与成本（1 张表）
11. 十一、风险提示与建议（风险、结果预判、类案参考 3 张表）
12. 十二、待办事项（1 张表）
13. 十三、材料完整性核查（1 张表）
14. 十四、矛盾信息登记（1 张表）
15. 十五、AI输出质量自检（质量自检表、签字/审核表 2 张表）

模板说明区（标题后的“使用说明”“适用范围”“AI处理规则”“常见案由速查”及所有示例/填写提示）
仅用于生成规则，不得进入正式报告；除此以外的正式章节、子标题和表格均不得删除、合并、改名或替换。

### 表格写入约束

1. 固定字段表只可替换内容值；不得改写左侧字段名、表头、合计行、空白签字位或原表格的合并和边框。
2. 数据表保留第 1 行表头；删除模板示例数据行后再写入实际数据行。若无数据，写一行 `【未载明】` 或 `【不适用】`，但不删除表头。
3. 第 33 表必须保留为未填写的人工签署区。不得让 AI 写入签名、审核姓名或日期，也不得在其后新增签名、审核或日期文本。
4. 所有来源定位写入相应的“来源材料”“对应证据”“附件编号”或备注列；没有来源不得写成确定事实。

## 内容映射

| 模板区域 | 规范化数据来源 | 规则 |
| --- | --- | --- |
| 一至二部分 | `case`、`parties` | 不推测受理机构、地址、律师、身份号码等未提供内容。 |
| 三、四、五部分 | `claims`、`timeline`、`disputed_facts`、`issues` | 每条事实保留来源材料和定位；法律分析栏仅转写材料支持内容或标为待人工审核。 |
| 六部分 | `evidence`、`missing_materials` | `证N（E00N）` 同时保留模板证据编号和稳定内部编号；三性、质证、补强不臆测。 |
| 七部分 | `amounts` | 每项显示金额编号、性质、角色、计算式和金额；利息/违约金无数据时填不适用。 |
| 八至十部分 | `procedure`、案件状态 | 未结案不得虚构裁判、二审、执行、费用数据。 |
| 十一部分 | `missing_materials`、`contradictions`、`review_notes` | 仅显示材料风险；胜诉概率、金额区间、和解建议、类案参考均写待人工审核。 |
| 十二至十四部分 | `todos`、材料清单、`contradictions` | 材料核查按当前上传材料逐项标明“是/否”，并给出材料编号或“当前已上传材料未见”。 |
| 十五部分 | `validate_case.py` 结果及云文档结构回读 | 有任一警告时，不得显示“通过”，应显示“待人工复核”。 |

## 增量更新

1. 输入必须包含同一案件的全部原始材料、当前报告以及案件标识。
2. 当前报告只用作版本基线；原始材料始终优先。
3. 新版云文档须写明更新版本、更新时间及 `new_material_scope`，并重新通过结构化与云文档结构校验。
4. 工作流保存新版本到历史记录后才更新案件主记录的当前报告；校验失败不得覆盖当前有效版本。

## 验收

云文档结构校验必须同时确认：模板十五部分齐全、34 张正式表的行列结构与固定表头齐全、
末页签字/审核表未经重写、结构化事实未遗漏、无模板说明/示例残留、无内部 JSON/Python 字段泄露。
还必须读取云文档结构，检查章节、表头、来源定位、空值标识和签字区是否存在乱码、
截断、表格错位、日期/签字栏异常或模板说明残留。
