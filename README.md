# 纠纷材料整理工作流组件 3.3.3

这是飞书多维表格的**记录级任务投递组件**。它不搬运附件二进制，而是在组件运行时完成目标记录预检、状态门禁和一次 Aily 智能体任务投递；智能体继续负责读取当前记录附件、创建原生飞书云文档、授予并核验上传人 `full_access`，以及最终同记录回写。

## 这次修复解决什么

线上截图中的失败发生在“纠纷材料整理”组件本身，步骤耗时约 1.2 秒，尚未进入长时间材料处理阶段。旧组件只接受案件编号、直接创建聊天，失败时抛出普通异常，既不能证明目标记录正确，也不能把失败原因可靠写回 Base。

3.3.3 进一步移除冗余的案件编号表单输入，改为：

```text
record_id + table_id
→ 精确读取同一条 Base 记录，并从记录读取案件编号
→ 检查 上传材料 / 上传人 / 当前状态
→ 写入并读回 状态=分析中
→ 只创建一次 Aily chat
→ 读回分析中状态
→ agent 使用同一 record_id 完成异步闭环
```

失败时组件会尝试对同一记录写入：

```text
AI分析结果 = 空
状态 = 分析失败
执行日志/失败原因 = build + stage + 可重试错误摘要
```

## 当前生产字段

| 用途 | 字段 | 责任 |
|---|---|---|
| 业务编号 | `案件编号` | 从精确记录读取，不作为组件输入或定位键 |
| 精确定位 | `record_id` | 组件和 Skill 的权威记录键 |
| 附件事实源 | `上传材料` | Skill 只读取本记录当前附件 |
| 权限接收人 | `上传人` | Skill 使用其 `open_id` |
| 执行状态 | `状态` | `待分析` / `分析中` / `待人工审核` / `已完成` / `分析失败` |
| 结果链接 | `AI分析结果` | 普通文本中的唯一裸 `/docx/<token>` URL |
| 失败留痕 | `执行日志/失败原因` | 技术阶段和错误摘要 |

旧名称 `案件文档`、`AI处理状态`、`待法务审核` 不再属于当前生产契约。

## 组件输入映射

- `recordId`：**必填且必须显式映射**新增/当前记录的 `record_id`；组件不再把案件编号当作记录定位替代品。
- `targetTableId`：**必填且必须显式映射**当前触发记录所属的数据表 ID；不要依赖未验证的上下文回退。

组件界面只保留这两个输入。案件编号由组件在 `table_id + record_id` 精确读取成功后从该记录取得，工作流无需重复映射。

**不要**从文件名、案件名称或案件编号模糊搜索来代替 `recordId`。

## Aily 侧前提

组件固定调用企业智能体：

```text
agent_4kuakyp7zsa2xuc
```

目标智能体必须实际安装并发布与组件同契约的 Skill，并拥有真实运行时能力：

1. 使用 `table_id + record_id` 读取同一条记录；
2. 读取 `上传材料` 正文；
3. 创建原生飞书云文档；
4. 对 `上传人.open_id` 执行 `member_type=openid`、`perm=full_access`；
5. 读回成员权限；
6. 回写同一记录并读回最终状态。

用户侧可读到 Base/Drive，不代表 Aily 智能体运行时拥有相同授权。必须在目标企业智能体的真实调试日志中看到本轮 `record_id` 的调用链。

## 本地验证

```bash
npm test
npm run build
```

测试覆盖：

- 精确 record/table 身份；
- Base 记录预检和字段一致性；
- 附件/上传人缺失拦截；
- `状态=分析中` 写入与读回；
- Aily 单次聊天创建；
- 同一记录失败回写；
- 已在途任务幂等，禁止第二个 chat；
- 租户凭证缺失诊断；
- Skill 3.3.3、当前字段和权限契约一致性。

## 线上发布顺序

组件上传、开放平台发布、Base 工作流重新绑定、目标 Agent Skill 安装/发布是四个独立状态，必须逐项核验。不能以“上传成功”代替“线上运行版本已切换”。

只在以下条件都具备后运行一条新的隔离记录：

- 工作流把 `recordId` 显式映射到组件；
- 目标 Agent 使用同一个 `record_id`；
- 目标 Agent 真实安装并发布 3.3.3 兼容 Skill；
- 目标 Agent 在日志中先调用 Base 精确读取工具；若工具不可用必须在短时间内返回 `BASE_CONNECTOR_UNAVAILABLE`，不得进入文件搜索循环；
- 线上日志出现 `build=3.3.3-record-id-only-dispatch`；
- Base 最终读回和目标上传人实际打开、编辑、管理协作者都通过。

本地构建和上传回执都不能替代上述线上证据。
